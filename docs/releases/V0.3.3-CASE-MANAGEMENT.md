# GTD Hub v0.3.3 — Full Case Management

## Release objective

Extend the v0.3.2 encrypted reporting foundation into an institution-scoped, human-led case-management workflow. Existing `secure_cases` references, ciphertext, consent values and audit history are retained. Migration `0005_case_management` is additive and follows `0004_secure_case_data`.

## Scope

- Case dashboard and institution-scoped work queues.
- Assignment to active Case Handlers within the case's institution, with assignment history.
- Human-recorded workflow transitions with explicit transition validation and decision codes where required.
- Human-set priority (`low`, `normal`, `high`, `urgent`); no algorithmic risk scoring.
- Structured case activity notes using predefined note codes only in this synthetic demonstrator; note payloads are encrypted with AES-GCM.
- Existing audit chain records assignment, workflow, note and priority events without sensitive narrative content.
- Programme Administrators retain programme-wide access; Case Handlers remain institution-scoped. Other roles are denied case-management access.

## Workflow states

`received -> acknowledged -> under_review -> information_only | referral_pending_human_action | institutional_action_pending_human_action | emergency_escalation_pending_human_action -> closed`

A closed case may be reopened to `under_review` by an authorised human handler. Valid transitions are enforced server-side. Closure requires a human decision code. Referral requires previously recorded consent. Staff cannot grant referral consent on a participant's behalf. The API records workflow intent only; it does not contact a provider, send an emergency alert, determine risk, or make a safeguarding decision.

## Data protection

- Assignment metadata is stored separately from encrypted report content.
- Case notes are predefined structured events and are encrypted at rest; arbitrary free-text notes are not accepted in this demonstrator.
- Case payload and note decryption remains permission- and institution-scoped.
- Access, assignment, workflow, notes and priority changes are audit-recorded.
- Encryption and audit keys remain external configuration, never source-controlled.

## Operational limitations

This remains a synthetic-data demonstrator. Real reporting, contact details, real survivor narratives, live referrals, emergency notifications, operational response timers and institutional safeguarding decisions must not be enabled until FAWEZI/BUSE approve the safeguarding protocols, staff roles, consent language, retention schedule, escalation contacts, MFA and operational controls. Production readiness requires independent security testing, partner-controlled key custody/recovery, TLS and encrypted backup verification, and the October 2026 developer Technical Paper review.
