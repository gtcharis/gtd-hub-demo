# GTD Hub v0.3.2 — Support, Safe Reporting and Secure Case Data

## Scope implemented in this candidate

- PostgreSQL migration `0004_secure_case_data` adds the support directory, secure case metadata/payload store and audit events.
- Three predefined synthetic reporting scenarios only; the API rejects free-text narratives and contact details by schema design.
- AES-256-GCM case payload encryption with a fresh 96-bit nonce and authenticated associated data bound to case reference, institution and schema version.
- Encryption and HMAC keys are independently supplied by the deployment environment. Missing, malformed or wrong-length keys fail closed.
- Anonymous mode does not link the case record or creation audit event to the submitter's account. Authentication, network, device and hosting metadata may still exist outside the case store; do not promise absolute anonymity.
- Case Handler reads and actions are restricted to their assigned institution. Programme Administrator retains the approved programme-wide access. Other roles do not receive case permissions.
- Referral workflow requires recorded consent; consent withdrawal is separately recorded. Referral, institutional action and emergency escalation remain pending human action; the application does not send notifications or decide outcomes.
- HMAC-SHA-256 chained audit events use a separate key. Audit reads verify the complete global chain; no narrative or contact details are included in audit events.
- Frontend reporting submits a predefined synthetic scenario to the API. The support page loads the published illustrative directory from the API.
- Optional HTTPS enforcement middleware is provided; production must set `REQUIRE_HTTPS=true` behind an HTTPS-terminating proxy.

## Required deployment configuration

`CASE_ENCRYPTION_KEY`, `CASE_ENCRYPTION_KEY_VERSION`, and `CASE_AUDIT_HMAC_KEY` must be configured as hosting secrets. Encryption and audit keys must be independent, 32 bytes before base64url encoding, partner-controlled and backed up securely. Never commit real keys or include them in a release archive. `REQUIRE_HTTPS=true` must be set in production. Apply migrations with `alembic upgrade head`.
